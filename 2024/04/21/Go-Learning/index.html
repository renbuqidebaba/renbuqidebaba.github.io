这篇是我 Go 语言的系统笔记，由两部分合并而成：博客上原有的 Runtime / GC / GMP 笔记，加上后来面试准备中补齐的语言基础、map、slice、channel、锁机制。原来的 Runtime 部分做了扩写和结构化，和新内容合并成一篇完整的 Go 知识梳理。

全文按「语言基础 → 运行时 → 数据结构 → 并发原语 → 锁」五层组织。

一、语言基础

协程是什么

一个 Goroutine 会以一个很小的栈启动（2KB 或 4KB），当遇到栈空间不足时，栈会自动伸缩。正因为初始栈这么小，才可以轻易实现成千上万个 goroutine 同时启动。

协程、线程、进程的区别（高频）

维度 说明
进程 具有一定独立功能的程序，是资源分配和调度的最小单位。有自己独立的内存空间，不同进程之间通过进程间通信来通信
线程 进程的一个实体，是内核态的，是 CPU 调度和分派的基本单位。线程间主要靠共享内存通信，上下文切换很快
协程 一种用户态的轻量级线程，拥有自己的寄存器上下文和栈。调度切换时把寄存器上下文和栈保存到别处，切回来再加载。因为操作栈不涉及内核切换开销，且可以不加锁访问全局变量，所以切换非常快

make 和 new 的区别（高频）

  • new 只用于分配内存，返回一个指向地址的指针。它为每个新类型分配一片内存，初始化为 0，返回类型 *T 的内存地址，相当于 &T{}
  • make 只可用于 slice、map、channel 的初始化，返回的是引用（可以直接用）

一句话记：new 返回指针、用于任意类型；make 返回可用实例、只用于三种引用类型。

如何高效拼接字符串

用 + 操作符拼接时，会对字符串进行遍历，计算并开辟一个新的空间来存储拼接结果。

最优解是 strings.Builder：用 WriteString() 拼接，内部实现是「指针 + 切片」，同时 String() 返回拼接结果时直接把 []byte 转换为 string，从而避免变量拷贝。

顺带说下字符编码：

  • ASCII 只需 7 bit 就能完整表示，但只能覆盖英文字母在内的 128 个字符
  • 为了表示世界上大部分文字系统，发明了 Unicode——它是 ASCII 的超集，为每个字符分配一个标准编号（Unicode CodePoint）
  • 在 Go 语言中这个编号称为 rune，是 int32 类型的别名（顺带一提，ASCII 里 a 是 97，A 是 65）
sample := "我爱GO"
runeSamp := []rune(sample)
runeSamp[0] = '你'
fmt.Println(string(runeSamp))  // "你爱GO"
fmt.Println(len(runeSamp))     // 4

defer 执行的时机和次序

  • defer 在 return 之后执行，但在函数退出之前——所以 defer 可以修改返回值
  • 执行顺序和调用顺序相反，类似栈的后进先出（LIFO）

常用场景：处理成对的操作，比如打开/关闭、连接/断开、加锁/释放锁。释放资源的 defer 应该直接跟在请求资源的语句后面。

一个容易踩的细节：为什么下面这种写法修改不了返回值？

原因是 Go 的返回机制决定了——执行完 return 后会创建一个临时变量保存返回值。但如果用的是有名返回值（比如 func test() (i int)），执行 return 时不会再创建临时变量保存，所以能修改成功。

结构体 tag 有什么用

tag 可以为结构体成员提供属性（标签）：

  • json: —— json 序列化 / 反序列化时的字段名称
  • db: —— sqlx 模块中对应的数据库字段名
  • form: —— gin 框架中对应的前端数据字段名
  • binding: —— 搭配 form 使用。默认如果没查找到结构体中的某个字段，值不报错、为空；binding: required 代表没找到就返回错误给前端

init 函数的初始化（高频）

init() 是 go 初始化的一部分：由 runtime 初始化每个导入的包。

需要注意初始化不是按照从上到下的导入顺序，而是按照解析的依赖关系——没有依赖的包最先初始化。

执行顺序：

import  →  const  →  var  →  init()  →  main()

一个包可以有多个 init 函数。

普通指针和 unsafe.Pointer 的区别

  • 普通指针（*int、*string）有明确的类型信息，编译器会进行类型检查和垃圾回收跟踪。不同类型的指针之间不能直接转换，这是 Go 类型安全的体现
  • unsafe.Pointer 是 Go 的通用指针类型，它绕过了 Go 的类型系统，可以与任意类型的指针相互转换
  • 关键是：unsafe.Pointer 不受类型约束，但仍受 GC 跟踪

反射与如何获取结构体的所有 tag

反射是指计算机程序在运行时可以访问、检测和修改它本身状态或行为的一种能力——动态地知道给定数据对象的类型和结构，并有机会修改它。

  • 反射将接口变量转换成反射对象 Type 和 Value
  • 反射可以通过反射对象 Value 还原成原先的接口变量
  • 反射可以修改一个变量的值，前提是这个值可以被修改

获取结构体所有 tag 的做法：用 reflect.TypeOf 获取对象类型，NumField() 获取成员数量，Field(i) 获取第 i 个成员的名字，再用 Tag 方法拿到标签。

import "reflect"

type Author struct {
    Name         int      `json:Name`
    Publications []string `json:Publication,omitempty`
}

func main() {
    t := reflect.TypeOf(Author{})
    for i := 0; i < t.NumField(); i++ {
        name := t.Field(i).Name
        s, _ := t.FieldByName(name)
        fmt.Println(name, s.Tag)
    }
}

（tag 就是 name string 后面 `json:name-field` 这部分。）

:= 与 = 的区别

  • := 用于短变量声明和初始化，可以定义一个新变量并赋值，比如 x := 10。这个语法糖会根据右边的表达式类型自动推导出左边变量的类型。注意：**:= 只能在函数内部使用，函数外部只能用 var 关键字**
  • = 用于变量赋值操作，把右边的值赋给左边的变量，比如 x = 20。只执行赋值，不做类型推导

如何控制协程的数量

用带缓冲区的 channel 来控制，相当于实现一个简单的协程池——超过 channel 容量的就被阻塞住了：

var wg sync.WaitGroup
ch := make(chan struct{}, 1024)
for i := 0; i < 20000; i++ {
    wg.Add(1)
    ch <- struct{}{}
    go func() {
        defer wg.Done()
        <-ch
    }()
}
wg.Wait()

defer 能捕获子 goroutine 的 panic 吗

不能。 它们处于不同的调度器 P 中。对于子 goroutine，必须通过 recover() 机制来恢复，然后结合日志打印（或者通过 channel 传递 error）。

有一个 G 一直占用资源怎么办？什么是 work stealing？

如果有个 goroutine 一直占用资源，GMP 模型会从正常模式转变为饥饿模式（类似 mutex 的做法），允许其它 goroutine 使用 work stealing 抢占（禁用自旋锁）。

work stealing 算法指的是：一个线程如果处于空闲状态，就帮其它正在忙的线程分担压力，从全局队列取一个 G 任务来执行，可以极大提高执行效率。

Go 里怎么实现面向对象

一句话概括：继承是编译时的特征，多态是运行时的特性。Go 中只有组合，而组合优于继承。

Go 实现面向对象的两个关键是 struct 和 interface：

  • 封装——对于同一个包，对象对包内文件可见；对不同包，需要将对象以大写开头才可见
  • 继承——编译时特征。在 struct 内加入所需要继承的类型即可
  • 多态——运行时特征。Go 的多态通过 interface 实现，类型和接口是松耦合的，某个类型的实例可以赋给它所实现的任意接口类型的变量。Go 支持多重继承，就是在类型中嵌入所有必要的父类型

组合形式——在结构体中嵌入其他类型的结构体，被嵌入的结构体可以访问嵌入它的结构体的字段和方法：

type Animal struct {
    name string
}

func (a *Animal) Speak() {
    fmt.Println("I am an animal.")
}

type Dog struct {
    Animal
}

func main() {
    d := Dog{}
    d.name = "Buddy"
    d.Speak() // 输出: I am an animal.
}

接口形式——一个类型只需要实现了接口中定义的所有方法，即可被视为实现了该接口，从而实现多态：

type animal interface {
    Speak()
}

type dog struct{ name string }
type cat struct{ name string }

func (d *dog) Speak() { fmt.Println("狗叫") }
func (c *cat) Speak() { fmt.Println("猫叫") }

func main() {
    sp := []animal{
        &dog{name: "qian"},
        &cat{name: "gou"},
    }
    for _, i := range sp {
        i.Speak()
    }
}

返回局部变量的指针安全吗

安全，这一点和 C++ 不同。 因为 Go 会进行逃逸分析——如果发现局部变量的作用域超过该函数，就会把指针分配到堆区，避免内存泄漏；否则分配在栈上。

Go 什么时候发生阻塞？调度器怎么做

  • 用于原子、互斥量或 channel 操作导致的 goroutine 阻塞——调度器会把当前阻塞的 goroutine 从本地运行队列 LRQ 换出，并重新调度其它 goroutine
  • 由于网络请求和 IO 导致的阻塞——Go 提供了网络轮询器（Netpoller）来处理，后台用 epoll 等技术实现 IO 多路复用

Goroutine 什么情况会内存泄漏？如何避免

Go 中内存泄漏分暂时性和永久性两类。

暂时性内存泄漏：

  • 获取长字符串中的一段，导致长字符串未释放。string 相比切片少了一个 cap 字段，可以把它当成一个只读的切片类型；获取长 string 或切片中的一段内容时，新生成的对象和老的共用一片内存空间，会导致老的资源暂时得不到释放
  • 获取长 slice 中的一段导致长 slice 未释放
  • 在长 slice 中新建 slice 导致泄漏

永久性内存泄漏：

  • goroutine 永久阻塞导致的泄漏
  • time.Ticker 未关闭导致泄漏
  • 不正确使用 Finalizer（Go 版本的析构函数）导致泄漏

协程泄漏（Goroutine Leak）

协程泄漏是指协程创建之后没有得到释放。主要原因可以从「阻塞」这个层面去思考：

  • 缺少接收器，导致发送阻塞
  • 缺少发送器，导致接收阻塞
  • 死锁——多个协程由于竞争资源导致死锁
  • 创建协程时没有回收

Go 的竞态条件了解吗

所谓竞态，就是当两个或以上的 goroutine 访问相同资源时对资源进行读/写。比如 var a int = 0，有两个协程分别对 a += 1，最后 a 不一定为 2，这就是竞态。

解决方式：使用互斥锁、channel，或者原子操作。

若干 goroutine 中有一个 panic 会怎样

有一个 panic，剩余的 goroutine 也会退出，程序退出。

如果不想程序退出，必须通过调用 recover() 方法来捕获 panic、恢复将要崩掉的程序。注意：recover 函数仅在 defer 函数中调用时才有效。

如何判断两个字符串切片是否相等

用 reflect.DeepEqual()——但反射非常影响性能。

var str [10]string
for i := 0; i < 10; i++ {
    str[i] = "a"
}
fmt.Println(str)
str1 := str[1:4]
str2 := str[5:8]
fmt.Println(str2, str1)
fmt.Println(reflect.DeepEqual(str1, str2))

一个协程被网络 IO 卡住，对应线程会被卡住吗

不会。 因为用的是 epoll，那是非阻塞调用——网络 IO 和系统调用的处理方式不一样。

epoll 用事件发生机制，只有对应的 fd 就绪后才进行处理，并写到就绪队列里。网络 IO 利用非阻塞，而系统调用会创建新的线程来接管其他 goroutine。

Go 的性能如何排查

用 pprof 进行 CPU 和内存分析：

  1. 引入 pprof 包：在 Go 程序中引入 net/http/pprof
  2. 启动 HTTP 服务器：通过启动一个 HTTP 服务器提供 pprof 的 web 接口
  3. 收集性能数据：使用 go tool pprof 命令收集 CPU 或内存分析数据
  4. 分析性能数据：通过文本、图形化界面或浏览器查看结果

几个零散但常考的细节

  • 结构体打印时：%v 输出各成员的值；%+v 输出各成员的名称和值；%#v 输出结构体名称和各成员的名称和值
  • go 里面的 int 和 int32 不是一个概念，取决于当时的操作系统
  • Go 语言中 interface 的内部实现包含 2 个字段——类型 T 和值 V，interface 可以使用 == 或 != 比较
  • 两个 nil 的值可能不等：interface 在运行时绑定值，只有值为 nil 时接口值才为 nil，但它与指针的 nil 不相等
  • Go 可以限制运行时操作系统线程的数量：使用 runtime.GOMAXPROCS(num int) 设置线程数目。该值默认为 CPU 逻辑核数，设得太大反而会引起频繁的线程切换，降低性能

二、运行时（Runtime）

golang 的 runtime 在 golang 中的地位类似于 Java 的虚拟机，不过 go runtime 不是虚拟机。

GC 机制

Go 1.8 采用并发三色标记法 + 混合写屏障。

GC 事件发生过程中会产生应用程序的停顿——停顿产生时整个应用程序线程都被暂停，没有任何响应，有点像卡死的感觉。这个停顿称为 STW（Stop The World）。

三色标记法

将对象标记为三种颜色：

  • 白色——不确定对象（默认色）
  • 黑色——存活对象
  • 灰色——存活对象，但子对象待处理

GC 的四个阶段：

  1. STW，开启混合写屏障，扫描栈对象
  2. 将所有对象加入白色集合，从根对象开始将其放入灰色集合。每次从灰色集合取出一个被引用的对象标记为黑色，然后遍历其子对象标记为灰色放入灰色集合；如此循环直到灰色集合为空。剩余的白色对象就是需要清理的对象
  3. STW，关闭混合写屏障
  4. 在后台进行 GC（并发）

Go 采用了写屏障技术：当对象新增或者更新时，会将其着色为灰色。

为什么需要混合写屏障？

基于插入写屏障和删除写屏障的方案，在结束时需要 STW 来重新扫描栈，带来性能瓶颈。

混合写屏障分四步：

  1. GC 开始时，将栈上的全部对象标记为黑色（不需要二次扫描，无需 STW）
  2. GC 期间，任何栈上创建的新对象均为黑色
  3. 被删除引用的对象标记为灰色
  4. 总而言之就是确保黑色对象不能引用白色对象

这个改进直接使得 GC 时间从 2s 降低到 2us。

GC 触发条件：

  • 当前内存分配达到一定比例则触发
  • 2 分钟没有触发过 GC 则触发 GC
  • 手动触发，调用 runtime.GC()

内存分配

Go 程序在启动时会首先向系统申请一块内存（虚拟地址空间），然后自己切成小块进行管理。申请的内存分成 3 个区域：spans、bitmap、arena。

  • arena 区域——就是我们所谓的堆区，Go 动态分配的内存都在这个区域。它把内存分割成 8KB 大小的页，一些页组合起来称为 mspan
  • bitmap——用来标记堆区使用的映射表，记录了哪些区域保存了对象、对象是否包含指针，以及 GC 的标记信息
  • spans 区域——存放 mspan 的指针，每个指针对应一页

GMP 调度机制

M 与 P 的数量没有绝对关系——一个 M 阻塞，P 就会去创建或者切换另一个 M。所以即使 P 的默认数量是 1，也有可能创建很多个 M 出来。

GMP 工作流程：

  1. 初始化——程序启动时会创建一定数量的 P，每个 P 都有一个本地队列。同时也会创建一些 M，这些 M 会尝试获取 P 并开始执行 Goroutine
  2. 任务分配——创建一个新的 Goroutine 时，它会被放入某个 P 的本地队列；如果本地队列已满，则放入全局队列
  3. 任务执行——M 从 P 的本地队列获取 Goroutine 并执行。如果本地队列为空，M 会尝试从全局队列或其他 P 的本地队列「窃取」Goroutine 来执行，这就是工作窃取算法
  4. 抢占与协作——较新的 Go 版本引入了抢占式调度，确保 Goroutine 公平执行

GMP 能不能去掉 P 层？会怎么样？

P 层的作用有两点：

  • 每个 P 有自己的本地队列，大幅度减轻了对全局队列的直接依赖，效果就是锁竞争的减少——而 GM 模型的性能开销大头就是锁竞争
  • 在 GMP 模型中也实现了 Work Stealing 算法，如果 P 的本地队列为空，会从全局队列或其他 P 的本地队列窃取可运行的 G 来运行，减少空转，提高资源利用率

M 的两种状态：

  • 自旋线程——处于运行状态但没有可执行 goroutine 的线程，数量最多为 GOMAXPROCS，若数量大于 GOMAXPROCS 就会进入休眠
  • 非自旋线程——处于运行状态且有可执行 goroutine 的线程

三、map

Go 的 map 底层是哈希表，由 hmap 结构体和多个 bmap 桶组成。线程不安全，无序。 要并发安全的话可以自己加锁或者用 sync.Map。

type hmap struct {
    count      int             // 元素数量
    flags      uint8           // 标志位
    B          uint8           // 指数，表示桶的数量为 2^B
    noverflow  uint16          // 溢出桶的数量（近似值）
    hash0      uint32          // 哈希种子
    buckets    unsafe.Pointer  // 指向桶数组的指针
    oldbuckets unsafe.Pointer  // 指向旧桶数组的指针（扩容时使用）
    nevacuate  uintptr         // 缩容时的进度指标
    extra      *mapextra       // 额外的溢出桶信息
}

type mapextra struct {
    overflow *[]*bmap // 溢出桶的切片
}

// 桶结构（bmap），通常称为"桶"
type bmap struct {
    // 包含8个key和8个value
    // 实际是运行时生成的动态结构
    tophash  [8]uint8  // 存储哈希值的高8位
    keys     [8]keytype
    values   [8]valuetype
    overflow *bmap     // 溢出桶链表
}

内存布局：

hmap
  |
  +---> buckets[] (桶数组，长度=2^B)
         |
         +---> bmap0: [tophash0..7][key0..7][value0..7][overflow]
         +---> bmap1: [tophash0..7][key0..7][value0..7][overflow]
         ...

插入操作

哈希表中的每个槽位称为一个桶（Bucket），每个桶可以存储一个或多个键值对。

  1. 向 map 插入键值对时，先计算键的哈希值，取哈希的低 B 位作为桶索引，确定对应的桶
  2. 在桶对应的 tophash 数组中查找空位。如果桶中没有该键，则将键值对插入到桶中的第一个空闲位置（哈希值的高 8 位存 tophash，然后存 key[i]、value[i]）
  3. 如果桶已满，则创建一个溢出桶，将键值对插入到溢出桶中

查找操作

  1. 同样计算键的哈希值，找到对应的桶
  2. 在桶中查找匹配的键，如果没有找到，则在溢出桶中继续查找

冲突处理

  • 桶内冲突解决（开放寻址法风格）——当 key 的哈希值映射到同一个桶时，在桶内线性查找空槽
  • 桶内满了之后创建溢出桶

动态扩容机制

装载因子 = 元素数量 / 桶数量。 Go 的默认装载因子约 6.5——意味着更稀疏的桶，查找更快但内存使用更多。

// 触发扩容的两个条件：

// 条件1: 装载因子过高
if h.count > 6.5 * (1 << h.B) {  // 装载因子 > 6.5
    hashGrow()  // 扩容
}

// 条件2: 溢出桶过多
if h.B < 15 && h.noverflow >= 1<<h.B {  // 溢出桶太多
    hashGrow()  // 扩容
}
if h.B >= 15 && h.noverflow >= 1<<15 {  // 溢出桶太多
    hashGrow()  // 扩容
}

Go 采用渐进式扩容，避免一次性搬迁的性能抖动。

四、slice

slice 本质是指针引用底层数组。一个切片由 3 部分组成：指针、长度、容量。

type slice struct {
    array unsafe.Pointer // 指向底层数组
    len   int            // 长度
    cap   int            // 容量
}

关键特性：改变 slice，也会改变之前的数组。（因为它只是底层的视图）

slice 和 array 的区别

  • slice——切片，是引用类型，长度可变
  • array——数组，是值类型，长度不可变（比如 [3]int 和 [4]int 是不同类型）

slice 扩容规则

  • 小容量时——如果原切片容量小于 1024 个元素，新容量变为原来的 2 倍。例如原容量 3，扩容后变成 6
  • 大容量时——如果原切片容量大于或等于 1024 个元素，新容量增加原容量的一半。例如原容量 2048，扩容后变成 3072（2048 + 1024）

五、channel

Channel 是 Go 语言中的一种并发原语，用于在 goroutine 之间传递数据和同步执行。

底层原理和数据结构

Channel 的底层是一个名为 hchan 的结构体，核心包含几个关键组件：

  • 环形缓冲区——有缓冲 channel 内部维护一个固定大小的环形队列，用 buf 指针指向缓冲区，sendx 和 recvx 分别记录发送和接收的位置索引。这样设计能高效利用内存，避免数据搬移
  • 两个等待队列 sendq 和 recvq——管理阻塞的 goroutine。sendq 存储因 channel 满而阻塞的发送者，recvq 存储因 channel 空而阻塞的接收者。这些队列用双向链表实现，条件满足时会唤醒对应的 goroutine
  • 互斥锁——hchan 内部有个 mutex，所有发送、接收操作都需要先获取锁，用来保证并发安全
type hchan struct {
    // channel分为无缓冲和有缓冲两种。
    // 对于有缓冲的channel存储数据，借助的是如下循环数组的结构
    qcount   uint           // 循环数组中的元素数量
    dataqsiz uint           // 循环数组的长度
    buf      unsafe.Pointer // 指向底层循环数组的指针
    elemsize uint16         // 能够收发元素的大小
    closed   uint32         // channel是否关闭的标志
    elemtype *_type         // channel中的元素类型

    // 有缓冲channel内的缓冲数组会被作为一个"环型"来使用。
    // 当下标超过数组容量后会回到第一个位置，所以需要两个字段记录当前读和写的下标位置
    sendx    uint   // 下一次发送数据的下标位置
    recvx    uint   // 下一次读取数据的下标位置

    // 当循环数组中没有数据时收到了接收请求，那么接收数据的变量地址将写入读等待队列
    // 当循环数组中数据已满时收到了发送请求，那么发送数据的变量地址将写入写等待队列
    recvq    waitq  // 读等待队列
    sendq    waitq  // 写等待队列

    lock     mutex  // 互斥锁，保证读写channel时不存在并发竞争问题
}

Channel 为什么能做到线程安全

Channel 的线程安全主要通过其内部的同步机制实现。

Channel 可以理解为一个先进先出的队列，通过管道进行通信。发送一个数据到 Channel 和从 Channel 接收一个数据都是原子性的。

不要通过共享内存来通信，而是通过通信来共享内存。

当多个 goroutine 通过 Channel 通信时，Channel 会保证每个操作的原子性和顺序性。

操作 Channel 可能出现的三种情况

nil、active、closed（已关闭）——不同状态下读写行为不同，nil channel 的读写会永久阻塞。

Channel 的读写是原子性的吗

是原子性的，由 Go 语言内部的同步机制保证，基于锁的同步和等待的同步。

如何避免 channel 死锁

三种手段：使用缓冲区、使用超时机制、使用 select。

Channel 的内存模型

Go 的 Channel 内存模型基于 CSP（Communicating Sequential Processes，通信顺序进程） 模型。

CSP 是一种并发计算模型，它将并发程序看作是一组顺序进程，这些进程通过 Channel 进行通信和同步。

六、锁机制

除了 mutex 还有什么方式安全读写共享变量

  • 把共享变量的读写放到一个 goroutine 中，其它 goroutine 通过 channel 进行读写操作。为什么可以？因为 channel 保证了串行访问：每次只有一个 goroutine 可以读写共享变量，当一个 goroutine 开始读写操作时其他 goroutine 会被阻塞，直到该 goroutine 完成操作并释放 channel
  • 用个数为 1 的信号量（semaphore）实现互斥

Go 如何实现原子操作

Go 实现原子操作，其根本是依赖底层 CPU 硬件提供的原子指令，而不是通过操作系统或更上层的锁机制。

具体来说，sync/atomic 包中的函数在编译时会被编译器识别，并直接转换成对应目标硬件平台（如 x86、ARM）的单条原子机器指令。

原子操作与互斥锁的区别

原子操作 互斥锁
层级 CPU 硬件层面的「微观」机制 操作系统或语言运行时提供的「宏观」机制
保护范围 单个数据（通常是整型或指针）的单次读改写 一个代码块（临界区），而不仅仅是单个变量
性能 极高，不涉及内核介入和 goroutine 挂起 获取锁失败时会让 goroutine 休眠，而不是空耗 CPU

mutex 底层怎么实现

mutex 底层是通过原子操作 + 信号量实现的：通过 atomic 包中的一些原子操作来实现锁的锁定，通过信号量来实现协程的阻塞与唤醒。

type Mutex struct {
    state int32
    sema  uint32
}
  • state 表示锁的状态，有锁定、被唤醒、饥饿模式等，并且是用 state 的二进制位来标识的
  • sema 表示信号量，mutex 阻塞队列的定位就是通过这个变量实现的，从而实现 goroutine 的阻塞和唤醒

mutex 的两种模式：normal 和 starvation

  • 正常模式——所有 goroutine 按照 FIFO 顺序进行锁获取，被唤醒的 goroutine 和新请求锁的 goroutine 同时竞争。通常新请求锁的 goroutine 更容易获取锁（因为持续占有 CPU），被唤醒的则不容易拿到。公平性：否
  • 饥饿模式——所有尝试获取锁的 goroutine 排队等待，新请求锁的 goroutine 不会进行锁获取（禁用自旋），而是加入队列尾部等待。公平性：是

关于自旋（Lock Spinning）：线程尝试获取锁时，如果发现锁已被占用，它不会立即放弃 CPU 进入睡眠（这会引起上下文切换开销），而是进入一个循环，反复检查锁的状态，直到锁被释放。

sync.Once 的作用与实现

sync.Once 的作用是确保一个函数在程序生命周期内，无论在多少个 goroutine 中被调用，都只会被执行一次。常用于单例对象的初始化，或一些只需要执行一次的全局配置加载。

type Once struct {
    done uint32 // 标识位
    m    Mutex
}

sync.Map 的底层原理

sync.Map 的底层核心是「空间换时间」——通过两个 Map（read 和 dirty）的冗余结构实现「读写分离」，最终达到针对特定场景的「读」操作无锁优化。

  • read 是一个只读的 map，提供无锁的并发读取，速度极快
  • 写操作则会先操作一个加了锁的、可读写的 dirty map
  • 当 dirty map 的数据积累到一定程度，或者 read map 中没有某个 key 时，sync.Map 会将 dirty map 里的数据「晋升」并覆盖旧的 read map，完成一次数据同步

适用场景：读多写少。 不适合写多读少——因为写用的是 dirty map，是需要加锁的。

小结

整篇的主线可以浓缩成一句话：Go 的高并发能力来自「用户态调度 + 通信代替共享」这套设计。

  • 用户态调度 → goroutine 切换不落内核，栈自动伸缩
  • GMP 三层结构 → 本地队列 + work stealing 减少锁竞争
  • channel 的 CSP 语义 → 「不要通过共享内存来通信，而是通过通信来共享内存」
  • 而 Runtime 侧（GC 三色标记 + 混合写屏障、map 渐进式扩容、slice 扩容规则）都是为了在降低 STW 与性能抖动这条线上做平衡
